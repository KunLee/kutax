# ADR 0002 — Private account administration and personal settings

Date: 10 October 2026. Status: accepted for the owner's explicitly requested user-management extension.

The owner selected administrator account management plus personal settings. Keep the existing Angular/ASP.NET Core Identity/PostgreSQL architecture and reviewed stable dependencies; no new packages are required. This extends M0 independently of receipt ingestion.

Use a framework Identity `Administrator` role. The development-only seed grants it to the existing synthetic owner without resetting that account. The explicit `--bootstrap-admin` operator command creates an administrator or grants an existing enabled account the role after checking its current password. New operator-created administrators must change their initial password. Administrator roles are never accepted from client request bodies. Browser management cannot disable, reset or alter administrator accounts, preserving access to the administration function; operators provision additional administrators explicitly.

Administrators manage ordinary accounts through `/api/users`: paginated/searchable list, creation, name/email updates, enable/disable, unlock and temporary-password reset. Personal endpoints are `/api/accounts/me/profile` and `/api/accounts/me/password`, using the authenticated identity rather than a caller-supplied owner ID. Email changes are administrator-controlled; there is no email delivery/verification workflow yet. Disabling preserves records. There is no hard-delete route.

Add `DisplayName`, `IsEnabled` and `MustChangePassword` to Identity users. The additive migration defaults existing users to enabled and does not alter their credentials or selected financial year. API responses expose only account metadata, never password hashes, security stamps or reset tokens.

Use Identity password validation, lockout and password reset/change methods. Created members and reset accounts must choose a different password before accessing workspace APIs. Only CSRF issuance, session inspection, logout and personal password change remain available while a password change is required. The UI presents this flow immediately. Administrator reset clears temporary lockout; disabling remains a separate persisted flag that unlocking cannot override.

Validate Identity security stamps on every request for this small personal deployment. Password changes retain the current session with `RefreshSignInAsync`; other sessions fail on their next request. Administrator edits save a fresh stamp with the account changes, and reset uses Identity's stamp update. Disabled users cannot sign in, and the API also checks enabled state for authenticated requests. All writes retain antiforgery protection. Successful administrator mutations log action and actor/target IDs without credential payloads. A durable audit trail remains a later feature.

Validation includes role/CSRF rejection, protected administrator accounts, attempted role overposting, password policy and current-password checks, forced password change, cross-session revocation, disabled login, unlock and search/pagination bounds. A service test optionally targets the actual app image using `KUTAX_APP_URL`, with PostgreSQL-backed synthetic fixtures and explicit cleanup; CI uses this mode. Browser checks cover desktop/mobile administration and profile persistence against the real Podman stack.

**Amended 13 October 2026.** Administrators can now manage other administrators (edit, disable/enable, unlock, reset password, delete) but never their own account. Their own account is changed in personal settings. The API also refuses to disable or delete the last enabled administrator. Accounts can be deleted only when they hold no import batches, receipt transactions or tax packs. Anyone with records is disabled instead, which blocks sign-in and keeps the records the ATO expects people to retain. Deletion removes the privacy preference and the Identity account, and is logged with actor and target. Temporary passwords are suggested in the browser from `crypto.getRandomValues` (16 characters, every character class) and can be replaced.

Email verification/delivery, self-service forgotten-password recovery, MFA, role editing in the UI and deleting accounts that hold records are deferred. Production operational controls from M6 still apply.
